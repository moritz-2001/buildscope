# Frequently edited expensive headers

Run `buildscope analyze-history RUN --days 90` explicitly in an available local source checkout. The analysis reads committed Git history anchored to the capture's saved commit and observation time, and saves the versioned `header-history.json` artifact. Reports and imported captures use that artifact without reading Git or fetching remote history. Use 180 days when you want all report windows available.

The report offers 30, 90 (default), and 180 day windows, target filtering, text filtering, server pagination, and per-header commit and rename evidence. Priority is the number of content-changing commits multiplied by associated dependent compilation milliseconds from the selected capture. It is a prioritization signal, not predicted wall-clock savings. Recorded textual processing time is separate and inclusive; nested header time can overlap.

Only successful managed profiles with observed successful work for every selected dependent unit, complete local history, and a saved window covering the requested window receive a score. Ordinary and partial captures retain known work and unit coverage, with priority unavailable. A shorter saved window, shallow repository, or 10,000-commit scan budget produces disclosed lower-bound counts. Missing analysis is shown explicitly with the analysis command. External/generated and untracked headers cannot be assigned committed history.

History follows the first-parent development line, compares merge commits against their first parent, and counts content changes once per commit/header (including creation). Pure renames do not count as edits. Git similarity detection follows renames backwards; undetected renames break continuity. Dirty/uncommitted edits are excluded. Paths are parsed as NUL-delimited bytes; non-UTF-8 historical paths cause incomplete coverage. No checkout, ref change, or remote fetch occurs.

`HistorySnapshot.version` identifies algorithm/schema version 1. `anchor` is the saved Git commit; `until_ms` is capture observation time; `since_ms` is the inclusive saved window boundary; `analyzed_ms` records when local analysis ran. `complete` describes local scan coverage, `notes` preserves limitations, and `files` contains portable header keys with distinct edit object IDs/timestamps and detected older-to-newer rename pairs. Ranking responses omit individual edit and rename arrays; detail requests include them. Unknown versions or mismatched anchors are rejected.
